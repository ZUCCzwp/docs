本指南说明如何在 **Claude Code** 中使用 ViraltokAI 的 LLM 能力。`claude-opus-5-5` 直接走 [Messages](/zh/api-reference/chat/messages)。其他模型仍可通过 **CC Switch** 转到 Chat Completions。

<Info>
脚本或后端调用 `claude-opus-5-5` 时，直接请求 `POST /api/v1/messages`。OpenAI 兼容模型请走 [Responses](/zh/api-reference/llm/integrations/codex) 或 [Chat Completions](/zh/api-reference/chat/completions)。
</Info>

## 开始之前

<Steps>
<Step title="获取 API Key">
  在 [ViraltokAI 控制台](https://api.viraltok.ai) 创建 Open API Key，并充值吉米币。
</Step>
<Step title="安装 Claude Code">
  ```bash
  npm install -g @anthropic-ai/claude-code
  claude --version
  ```
</Step>
<Step title="安装 CC Switch（推荐）">
  从 [CC Switch 官网](https://cc-switch.cc) 或官方 GitHub Releases 安装，并保持为最新稳定版。
</Step>
</Steps>

## Claude Opus 5.5：直连 Messages

```bash
export ANTHROPIC_BASE_URL=https://api.viraltok.ai/api/open-api
export ANTHROPIC_API_KEY=YOUR_API_KEY
export ANTHROPIC_MODEL=claude-opus-5-5
claude
```

Base URL 不要再加 `/v1`。客户端会请求 `/v1/messages`。`claude-opus-5.5` 与 `claude-opus-55` 会归一化为 `claude-opus-5-5`。

## 其他模型：CC Switch + Chat Completions

数据流如下：

```text
Claude Code  →  Anthropic Messages  →  CC Switch（127.0.0.1）  →  ViraltokAI Chat Completions  →  转回 Messages
```

### 1. 在 CC Switch 中创建 Provider

| 字段 | 值 |
| :--- | :--- |
| API 请求地址 | `https://api.viraltok.ai/api/open-api/v1` |
| 完整 URL | **关闭** |
| 默认模型 | `claude-sonnet-5` 或 `gpt-5.6-sol` / `gpt-5.6-terra` |
| 上游格式 | **Chat Completions（需开启路由）** |
| API Key | 你的 ViraltokAI Open API Key |

<Note>
模型 ID 必须与 ViraltokAI 控制台中的计费 ID **完全一致**。`claude-opus-5-5` 不要配在这里，请用上面的 Messages 直连。
</Note>

### 2. 开启 Claude Code 路由

在 CC Switch：**Settings → Routing → Local Routing**

1. 打开本地路由总开关
2. 在 **Routing Enabled** 中开启 **Claude Code**（或对应 Claude 客户端项）
3. 启用上一步创建的 provider
4. 保持 CC Switch 运行

接管后，Claude Code 的 API 根地址应指向本机代理（常见为 `http://127.0.0.1:15721`），由 CC Switch 转发至 ViraltokAI。

### 3. 重启 Claude Code

完全退出 Claude Code 或 IDE 扩展后重新打开，避免缓存旧 provider。

## 直连 API（脚本 / 后端，非 Claude Code CLI）

OpenAI 兼容集成**默认使用 Responses**：

```bash
curl -X POST 'https://api.viraltok.ai/api/v1/responses' \
  -H 'Authorization: Bearer YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "claude-sonnet-5",
    "input": "用一句话介绍 ViraltokAI。"
  }'
```

若你的 SDK 只支持 Chat Completions，可使用 [Chat Completions](/zh/api-reference/chat/completions)：

```bash
curl -X POST 'https://api.viraltok.ai/api/v1/chat/completions' \
  -H 'Authorization: Bearer YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "claude-sonnet-5",
    "messages": [
      { "role": "user", "content": "用一句话介绍 ViraltokAI。" }
    ]
  }'
```

流式请求将 `"stream": true`，计费以最后一个带 `usage` 的事件或 chunk 为准。

<Warning>
`claude-opus-5-5` 可以把 `ANTHROPIC_BASE_URL` 设为 `https://api.viraltok.ai/api/open-api`。`claude-sonnet-5` 与 GPT 模型仍是 OpenAI 兼容协议，不要把它们的 Base URL 指到 Messages。
</Warning>

## 支持的模型

| 模型 ID | 典型用途 |
| :--- | :--- |
| `claude-opus-5-5` | Claude Opus 5.5。仅 [Messages](/zh/api-reference/chat/messages) |
| `claude-sonnet-5` | 代码与对话，Claude 档位 |
| `gpt-5.6-sol` | 通用推理与编码 |
| `gpt-5.6-terra` | GPT-5.6 Terra 档位 |
| `deepseek-v4.1-flash` | DeepSeek V4.1 Flash |

定价与倍率见 [查询探测模型定价](/zh/api-reference/common/model-catalog)（`model_type = llm`）。

## 计费说明

- 按响应 `usage` 中的 token 从吉米币扣费（输入 / 输出 / 缓存读 / 缓存写）。
- 余额不足时，请求会在转发上游前被拒绝；请先 [查询用户账户余额](/zh/api-reference/common/user-balance)。
- 控制台可查看 `msg_`（Messages）或 `chat_`（Chat Completions）前缀任务与用量明细。

## 故障排查

| 现象 | 处理 |
| :--- | :--- |
| 401 / Key 无效 | 确认 CC Switch 中保存的是 ViraltokAI Open API Key |
| 模型不存在 | 在控制台确认模型已启用，且 `model` 字段与计费 ID 一致 |
| 连接 localhost 失败 | 确认 CC Switch 本地路由已开启且进程在运行 |
| 有回复但未扣费 | 检查响应是否包含 `usage`；流式需最后一个带 usage 的 chunk |

本指南说明如何将 **OpenAI Codex**（CLI、IDE 扩展或读取同一套 `config.toml` 的桌面客户端）指向 ViraltokAI 的 LLM 接口，使用 `gpt-5.6-sol`、`gpt-5.6-terra`、`claude-sonnet-5` 等模型，并按 token 从吉米币（JimiCoin）扣费。

<Info>
**默认走 Responses API。** Codex 与 ViraltokAI 均以对 `POST /api/open-api/v1/responses` 的 OpenAI Responses 协议为首选路径。仅在旧工具链或 CC Switch 无法使用 Responses 上游格式时，才回退到 Chat Completions。
</Info>

<Note>
Codex 云端会话目前**不能**通过自定义 `model_provider` 切换为第三方模型。以下步骤仅适用于**本机** Codex。
</Note>

## 开始之前

<Steps>
<Step title="获取 API Key">
  在 [ViraltokAI 控制台](https://api.viraltok.ai) 创建 Open API Key，并确保账户吉米币余额大于 0。
</Step>
<Step title="安装或更新 Codex CLI">
  ```bash
  npm install -g @openai/codex@latest
  codex --version
  ```
  首次安装后至少运行一次 `codex`，以生成 `~/.codex/config.toml`。
</Step>
<Step title="确认模型与定价">
  在 [查询探测模型定价](/zh/api-reference/common/model-catalog) 中筛选 `model_type = llm`，或搜索 `gpt-5.6-sol`。计费规则见 [Chat Completions](/zh/api-reference/chat/completions#usage-与计费)。
</Step>
</Steps>

## 接入方式概览

| 方式 | 优先级 | Codex 协议 | ViraltokAI 端点 |
| :--- | :--- | :--- | :--- |
| **直连 Responses** | **默认 / 推荐** | Responses | `POST /api/open-api/v1/responses` |
| **CC Switch + Responses 上游** | 需本地代理时 | Responses → 直连 | `POST /api/open-api/v1/responses` |
| **CC Switch + Chat 转换** | 仅作回退 | Responses → 转换 → Chat | `POST /api/open-api/v1/chat/completions` |

两种方式的 **Base URL 根路径相同**（不要重复拼接 `/responses` 或 `/chat/completions`）：

```text
https://api.viraltok.ai/api/open-api/v1
```

鉴权：

```http
Authorization: Bearer <YOUR_API_KEY>
```

---

## 默认：直连 Responses API

Codex 默认使用 **OpenAI Responses API**（`wire_api = "responses"`，省略时也是 `responses`）。ViraltokAI 提供兼容的 `POST /responses`，**无需**协议转换。

### 1. 设置环境变量

```bash
export VIRALTOK_API_KEY="你的_OpenAPI_Key"
```

### 2. 编辑 `~/.codex/config.toml`

```toml
model_provider = "viraltokai"
model = "gpt-5.6-sol"

[model_providers.viraltokai]
name = "ViraltokAI"
base_url = "https://api.viraltok.ai/api/open-api/v1"
wire_api = "responses"   # 默认；可省略，效果相同
env_key = "VIRALTOK_API_KEY"
model = "gpt-5.6-sol"
```

将 `model` 换成你需要的计费模型 ID，例如 `gpt-5.6-terra` 或 `claude-sonnet-5`。

<Warning>
不要设置 `wire_api = "chat"`。新版 Codex 已弃用该选项，且 ViraltokAI 的长期推荐路径是 Responses API。
</Warning>

### 3. 验证

在 Codex 中运行 `/status` 与 `/debug-config`，确认 `base_url` 指向 ViraltokAI 且 `wire_api` 为 `responses`。

用 curl 快速探测（应返回鉴权或参数类 JSON，而不是 `404 page not found`）：

```bash
curl -s -o /dev/null -w "%{http_code}\n" \
  -X POST 'https://api.viraltok.ai/api/open-api/v1/responses' \
  -H 'Authorization: Bearer YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"model":"gpt-5.6-sol","input":"hi"}'
```

## CC Switch：优先 Responses 上游

若使用 CC Switch 管理 provider，**不要将上游格式设为 Chat Completions**，除非 Responses 不可用。正确配置：

| 字段 | 值 |
| :--- | :--- |
| API 请求地址 | `https://api.viraltok.ai/api/open-api/v1` |
| 完整 URL | **关闭** |
| 默认模型 | `gpt-5.6-sol`（或 `gpt-5.6-terra` 等） |
| 上游格式 | **Responses（原生）** — 直连，不做 Chat 转换 |

在 CC Switch：**Settings → Routing → Local Routing** 中开启 Codex 接管。Codex 仍走 Responses；CC Switch 转发到 ViraltokAI 的 `/responses`。

接管成功后，`~/.codex/config.toml` 的 `base_url` 应类似 `http://127.0.0.1:15721/v1`，而不是直接指向 `api.viraltok.ai`。

---

## 回退：CC Switch + Chat Completions

仅当 Responses 上游不可用时才选用。上游格式选 **Chat Completions（需开启路由）**，由 CC Switch 将 Codex 的 Responses 请求转换为 [Chat Completions](/zh/api-reference/chat/completions)。

## 常见错误

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| 404，`url: …/v1/responses` 且 host 为 `api.viraltok.ai` | `/responses` 未部署或路径错误 | 确认平台已上线 Responses；Base URL 只填根路径 |
| CC Switch 选了 Chat 格式仍 404 到 `/responses` | **未接管** Codex，请求直连 ViraltokAI | 开启本地路由，确认 `127.0.0.1:15721` |
| 误用 `wire_api = "chat"` | Codex 已弃用 Chat 直连 | 改为 `wire_api = "responses"` 或省略 |
| 401 / 余额不足 | Key 无效或吉米币为 0 | 检查 Key 与 [账户余额](/zh/api-reference/common/user-balance) |

## 支持的模型

| 模型 ID | 说明 |
| :--- | :--- |
| `gpt-5.6-sol` | 常用默认模型 |
| `gpt-5.6-terra` | GPT-5.6 Terra 档位 |
| `claude-sonnet-5` | Claude Sonnet 档位 |

部分别名（如 `gpt-5.6`、`gpt5.6-sol`）会在 Chat Completions 路径下归一化为 `gpt-5.6-sol`。Responses 路径请使用上表中的**完整模型 ID**。

---

## 计费与用量

- 成功响应中的 `usage`（或流式最后一个带 `usage` 的事件）用于按量扣费。
- 支持输入、输出、缓存读、缓存写四段 token 计费，公式见 [Chat Completions — Usage 与计费](/zh/api-reference/chat/completions#usage-与计费)。
- 任务 ID 前缀：`resp_`（Responses）或 `chat_`（Chat Completions）。
